# 代码/评测/ · 验证集评测

赛题要求提交「在给定/自备验证集上的评测结果」。本目录提供**可复现的评测脚本与结果**。

```
代码/评测/
├── run_eval.py          评测脚本（六项指标，两种模式）
├── results/
│   ├── report.md            人类可读报告（由最新一轮运行生成）
│   ├── latest_cloud.json    最近一次云端模式完整结果
│   ├── latest_local.json    最近一次离线模式完整结果
│   └── eval_<模式>_<时间戳>.json  历史结果
└── external/            外部验证集投放目录（把 .pdf/.docx 放进来即自动纳入）
```

## 怎么跑

```bash
# 在项目根目录执行
python -X utf8 代码/评测/run_eval.py            # 仅云端（需在 .env 填百炼 Key）
python -X utf8 代码/评测/run_eval.py --local    # 仅离线（随包本地模型）
python -X utf8 代码/评测/run_eval.py --all      # 两种模式依次跑，生成对比报告
```

前置条件：文献库中已有已解析的论文（`python -X utf8 -m 源程序 demo` 会准备 6 篇示例论文），
且已生成过一轮草稿与自检结果。

## 六项指标

| # | 指标 | 说明 |
|---|---|---|
| 1 | 文献库解析质量 | 正文字符、章节数、参考文献条数、非论文误判 |
| 2 | **引用错误检出** | 专家注入 4 类错误，测查全率与**类别命中正确率** |
| 3 | **误报控制** | 用"干净稿"测引用类误报数（报得多 ≠ 报得对） |
| 4 | RAG 证据核对 | 论断能否在对应论文原文找到依据（支持率） |
| 5 | GB/T 7714 格式合规 | 参考文献表逐条校验 |
| 6 | 检索质量 | 论断能否成功定位到原文片段 |

## 两个必须注意的口径问题

**⓪ 复现前请先准备好模型通道。**

`代码/评测/results/` 里**已附上交付环境实测的结果**（`report.md` 与 `latest_*.json`），可以直接引用。
但两份 latest 的**判定机制不同，支持率不可互比**：

- `latest_cloud.json`：云端模式，模型逐条判定（`判定机制 = 模型逐条判定检索到的原文片段`）；
- `latest_local.json`：本地模式那一轮**判定退化为相似度阈值兜底**
  （`是否启用模型判定 = false`，0.6 秒跑完），它给出的支持率会虚高。

引用哪一份，请连口径一起写（见《02_验证集评测结果》§4.1）。

若要自己重跑，必须至少满足其一：

- 在 `.env` 里填入**你自己的**百炼 API Key（提交版刻意放的是占位符），或
- 确保随包本地模型可用（`代码/源程序/models/` 完整、llama-server 能启动）。

两者都没有时，检索环节没有可用的嵌入与查询生成能力，各处相似度为 0，
「支持率」会显示 **0.0**——那是**环境缺模型**导致的，不是程序算错。

> **关于随包的 `代码/源程序/.cache/`：本提交包保留了它（实测 3,357 个文件 / 46.7 MB，
> 其中 208 条响应缓存 + 3,148 个嵌入向量）。**
> 该缓存保存此前云端调用的响应，且缓存键**不含 API Key**。保留它的理由与代价都要说清：
>
> - **理由**：本地模型在 CPU 上无法保证长序列逐位可复现，缓存是让演示与评测
>   在无网/无 Key 时也能复现历史结果的**手段**。
> - **代价（必须知道）**：**用无效 Key 也可能"看起来跑通了云端"**——因为命中了缓存。
>   要验证云端通道真的可用，请**先清空该目录**再用有效 Key 运行；
>   清空后行为与配置一致：有 Key 就走云端，没 Key 就退回本地通道。
> - 清空该目录只影响"下次重算"，不会丢数据或产物；包体也会相应减少约 42 MB。

**① 支持率不可跨模式比较。** 启用模型时由模型逐条判定；未启用模型时退化为
「相似度 ≥ 0.15 即算有支撑」，后者几乎不会判无支撑，支持率会**虚高**。
脚本在 JSON 中记录 `判定机制` 与 `跨模式可比性` 两个字段，报告里也加了警告。

**② 否定式论断存在已知误报。** 形如「所有方法均未超越 X」的表述，原文对应的是
「性能低于…」，检索难以命中，易被判为无支撑。详见 `文档与参考/交付文档/02_验证集评测结果.md` §4.2。

## 扩展外部验证集

把任意 `.pdf` / `.docx` 放入 `代码/评测/external/`，重跑脚本即自动纳入。

- **天池 CSL 中文文献数据集**（约 39.6 万篇论文的标题/摘要/关键词元数据）：
  该数据集**不含全文**，因此在本作品中主要用于「题录导入」与「原文缺失」路径的验证。
- 自己领域的论文：最能暴露跨领域失效，建议优先补。

当前内置集为 6 篇论文 + 4 类注入错误，规模偏小——它验证的是**功能正确性**，
不足以给出统计意义上的精度指标。详见评测报告 §4.3。

# 文脉 WenMai

**文献综述写作与引用自检助手**

> 把一批论文变成你能直接交上去的综述稿 —— 自动排好 GB/T 7714 参考文献，并逐条自查引用是否真实、格式是否合规。

2026 年第二届重庆市 AI 大模型创新应用大赛 · 企业出题赛道 · 阿里「创意 AI 校园」
赛题归类：科研创新 —— 文献综述助手　｜　技术路径：路径 C（RAG + 微调），并入 Agent 能力

---

## 一、它解决什么问题

写毕业论文、做大创、跟导师做科研的本科生，手上通常有 30–50 篇 PDF：读完要两三周，读完了还要面对最烦的一件事——**参考文献格式（GB/T 7714）和引用编号，错一处就要返工**。

现有工具帮你"读懂"，但**不帮你"交得出去"**。

文脉做两件事：

1. **把出口做实用** —— 输出可直接使用的 Word 稿件，参考文献自动按 GB/T 7714 排好；
2. **把可信度做硬** —— 生成之后**自动自检**：引用是否真实、编号顺序对不对、格式合不合规、有没有该引没引。

## 四、它怎么工作

```
① 导入文献（PDF，或 OpenAlex 开放获取）
        ↓
② 解析：全文、摘要、章节、参考文献区、局限句、贡献句
        ↓
③ 文献卡片：解决什么问题 / 方法 / 数据 / 指标 / 局限 / 可借鉴点
        ↓
④ 主题聚类 + 对比矩阵（可导出 Excel）
        ↓
⑤ 起草综述：正文带 [n] 引用角标；编号由程序统一分配
        ↓
⑥ 引用自检（7 项）+ 埋错测试
        ↓
⑦ 导出 Word（正文 + GB/T 7714 参考文献 + 自检报告）
```

### 关键设计

- **引用编号由程序分配，不让模型自由编号**。生成后按正文首次出现顺序重排（顺序编码制），并**剔除未被引用的条目**——保证"正文角标 ↔ 文末条目"严格一一对应。
- **RAG 检索环节（真正的 R）**：把每篇论文全文切成语义完整的段落并建立索引；
  正文每一处引用都会**回到对应论文原文检索证据**，再由模型判断该论断是否成立。
  检索用**阿里云百炼 text-embedding-v3** 语义向量（跨语言/跨表述匹配），
  断网时退回本地字符 n-gram，保证可演示。
- **Agent 审稿**：模型**自主决定**调用哪些工具（读全稿 → 挑可疑项 → 回原文核对 → 出报告），
  不是固定顺序跑一遍。可用 `python -X utf8 -m 源程序 agent` 或界面上的「开始智能审稿」触发。
- **双通道**：本地通道（规则 + BM25 + 哈希向量）始终可用、零成本；模型通道（百炼）有网络时自动增强。任一步失败都不中断流程。

## 五、引用自检的 10 项检查

| # | 检查项 | 说明 |
|---|---|---|
| 1 | **引用真实性** | 正文角标 [n] 在参考文献表中是否存在 |
| 2 | **文末未引用** | 文末条目是否在正文中从未出现 |
| 3 | **编号顺序** | 角标是否按首次出现顺序递增（顺序编码制） |
| 4 | **格式合规** | 逐条对照 GB/T 7714（作者/题名/类型标识/出版项/年份/访问路径） |
| 5 | **重复著录** | 同一文献被著录两次、编号重复 |
| 6 | **论断有据** | 回原文检索后，那句话在对应论文里找不到支撑 |
| 7 | **引用越界** | 编号超出参考文献表范围 |
| 8 | **原文明确矛盾** | 正文的数值或方向与原文冲突（如正文写「提升 10 倍」而原文是 2 倍） |
| 9 | **原文缺失（无法核对）** | 该文献原文不在库里（只导入题录、或解析失败）——**不是引用写错** |
| 10 | **该引未引** | 像研究结论却没有任何引用标注的陈述 |

报告输出：每处问题带**严重度、位置、详情、修改建议**，并写入 `outputs/selfcheck.json`。
除第 6、10 项外都是**确定性规则**，不依赖模型，因此断网时依然全部有效
（第 10 项依赖语义检索、界面标注"仅供参考"）。
「检查我的稿子」模式另有一项**引用可核实性**——稿子引的文献在你已导入的文献库里能否找到，
只导入题录时也可判定；十项检查与它的一一对应见《01_模型与算法说明》§6.3。

### 回原文核对：四态判定

「论断有据」这项会回到你引用的那篇论文原文里检索证据，逐条给出**四种**结论。
分开报是刻意的——把「没找到依据」和「原文说的正好相反」混成一个标签，
用户就分不清"你去核对一下"和"你写错了"：

| 结论 | 含义 | 该怎么处理 |
|---|---|---|
| **有依据** | 原文片段确实讲到该句的核心内容 | 无需处理 |
| **找不到依据** | 检索到段落，但它讲的是别的事 | **不等于引用写错**，可能只是原文换了措辞；点开原文片段自行判断 |
| **原文明确矛盾** | 正文的数值或方向与原文冲突 | 硬结论：以原文为准修改论断，或更换引用 |
| **无法核对** | 该文献原文不在库里（只导入题录、或解析失败） | 不是引用问题；把原文导进来即可核对 |

「原文明确矛盾」由**确定性比对**判定，不靠模型自由裁量：同量纲数值不一致、
论断数值在原文中不存在（仅同语言时）、方向相反（提升 vs 降低）。
判定刻意保守——**宁可漏报，也不把"没找到"说成"写错了"**，
误报几次用户就再也不信这个工具。

每条结论都带**原文片段与页码**，可以翻回原文自己核对。

### 自检能力验证：埋错测试

向文本中**人为注入已知错误**，验证自检能否检出——指标客观、可复现、无法造假。

| 注入的错误类型 | 检出情况 | 检出的问题类别 |
|---|---|---|
| 错编号顺序 | ✅ 已检出 | 编号顺序 / 文末未引用 |
| 假引用（[99] 不存在） | ✅ 已检出 | 引用真实性 / 引用越界 |
| 缺文献类型标识 | ✅ 已检出 | 格式合规 |
| 重复著录 | ✅ 已检出 | 重复著录 |

**四类全部检出（4 类各注入 1 处，共 4 处）**，结果见 `outputs/selfcheck_benchmark.json`。

> **口径要写清楚**：n=4，它证明的是"这四类独立成因各自都能被检出"，
> **不是**统计意义上的查全率。另外注入器与检查器同在 `selfcheck.py` 内，
> 属于自己出题自己判——这两点都如实标注，不做过度主张。

## 七、数据保存在哪里

**所有数据都在磁盘文件里，关掉程序、关掉电脑都不会丢。** 服务本身不保存状态，每次启动都是从 `data/` 和 `outputs/` 读回来——这一点由双重启测试实测过（见下）。

| 数据 | 位置 | 关掉程序后 |
|---|---|---|
| 文献库（含上传的 PDF） | `data/corpus.json` + `data/pdf/` | 保留 |
| 论文解析结果 | `data/docs.json` | 保留 |
| 卡片、对比矩阵 | `data/cards.json`、`data/matrix.json` | 保留 |
| 综述稿、自检报告、Word/Excel | `outputs/` | 保留 |
| 我上传的稿子 | `data/mydraft/` | 保留 |
| 云端/仅本地 的选择 | `data/privacy.json` | 保留 |
| 向量与模型回复缓存、成本台账 | `代码/源程序/.cache/` | 保留（可删，删了只是下次重算） |

**会丢数据的只有三种操作**，都是你主动做的：

1. 点界面上的「清空文献库」→ 清空 `corpus.json` 与解析/卡片/矩阵结果（`data/pdf/` 里的 PDF 文件保留）
2. 点某篇论文的「删除」→ 删掉该篇记录与其 PDF
3. 手动删掉 `data/` 或 `outputs/` 目录

**换电脑/备份**：整个项目目录拷走即可，`data/` 与 `outputs/` 一并在内。只想备份成果的话，拷 `data/` 和 `outputs/` 两个目录就够（`代码/源程序/.cache/` 不必备份，会自动重建）。

## 十、已知限制

| 限制 | 说明 | 缓解 |
|---|---|---|
| 模型偶尔漏标注引用 | 综合论断有时不带角标 | 程序对首句/总结句按同段编号补全；漏网者由自检报出 |
| 中文 PDF 解析未充分验证 | 当前实测样本为英文 arXiv 论文（8–15 页） | 中文期刊多为双栏/扫描件，需后续补充测试 |
| 参考文献条数识别不稳 | 部分 PDF 的参考文献区编号格式不同（实测 0–64 条） | 不影响卡片与草稿，仅影响引用数统计 |
| 章节标题识别不稳定 | 依赖排版，实测每篇识别 4–6 个章节 | 已用"摘要/方法/结论"多线索兜底 |
| 未使用 GPU 微调 | 学生专区无 GPU 机型，改为"平台内精调"或"严格 JSON + 校验重试"替代 | 见《文脉_方案_v1.1》§5.3「微调路径与实施说明」 |
| **「原文明确矛盾」偏保守** | 只认数值与方向这类能站得住的冲突；文字层面的矛盾（如「原文未讨论」而实际讨论了）交给模型判断，可能漏报 | 界面给出原文片段与页码，请以自己看到的内容为准 |
| **跨语言不判数值矛盾** | 中文论断写「提升 2 倍」而英文原文写 "two times" 时，数字形态不同，系统不判矛盾（否则会大量误报） | 同语言时才会用"数值在原文中不存在"这条 |

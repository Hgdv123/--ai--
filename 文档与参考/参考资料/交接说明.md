## 二、本次会话修掉的 5 个真 bug

每一个都有实测证据，不是推测。

### 1. 离线模式说"模型不可用"（用户首次报障）

- **根因**：`agent._chat_with_tools()` **完全没有本地分支**，永远拿 `settings.api_key` 请求阿里云端点。Key 是中文占位符 → `urllib` 按 latin-1 编码请求头 → `UnicodeEncodeError` → 直接放弃。更前面一道闸 `run()` 判断 `if not self.client.available`，而 `client.available` 用 `bool(api_key)` 判断，占位符"非空"被当成可用 → 走进云端分支再失败。
- **那句"模型不可用"从头到尾不成立**：本地模型一直是好的。
- **判据三处各错一遍**（`agent.py` / `llm.py` / `config.py`），已统一到 `config.key_usable()`。
- **修**：`_chat_with_tools()` 加本地分支；`run()` 闸门改为 `client.available or local_llm.available("gen")`；`cloud` 判据统一用 `key_usable()`。

### 2. `_healthy()` 把"忙"当成"没起来"

- **根因**：探活超时仅 2 秒且只认 HTTP 200。llama-server 在大提示词推理时无暇应答 `/health` → 被判"没起来" → `_start()` 另起实例抢同一端口 → 必然失败 → 报"llama-server 未就绪或返回异常"。
- **修**：有 HTTP 应答即算活着（503 = 忙）；但**端口在监听 ≠ 已就绪**（llama-server 先监听、后加载模型，那段窗口请求回 503），就绪一律以 `/health` 返回 200 为准，已监听的实例则等它就绪。
- **实测**：真实推理期间探测 37 次，37/37 判为活着；端口上始终 1 个实例。

### 3. 启动脚本崩溃（我自己引入的回归，务必引以为戒）

- **根因**：把 `python -X utf8 -m 源程序` 替换成实际包名时，`%s` 格式化被字符串拼接打断 —— **`%` 的优先级高于 `+`**，`"…%s…" + PKG + "…" % data_dir` 里的 `%` 只作用于最后一段 → `TypeError: not all arguments converted during string formatting` → `cmd_demo` 崩 → **服务根本起不来**。
- **修**：把格式化参数合并进一个 `%` 元组。
- **教训**：改打印文案后必须真跑一次启动，不能只看 `py_compile`。

### 4. 主按钮永久变灰（用户报"点不了"）

- **根因**：`btn-run` 在 HTML 里默认 `disabled`，只有 `refresh()` 成功才解开；而**服务不可达时 `refresh()` 直接 return**，那句"解开按钮"永远执行不到。服务一旦出问题，按钮就永远是灰的。
- **修**：失败分支也解开按钮并提示「服务尚未就绪，正在自动重试」；首屏不再写死 `disabled`；生成中不用 `disabled` 改用 `.running` 样式 + **15 分钟看门狗**自动复位 `busy`。
- **实测**：用本地文件加载页面模拟服务不可达，按钮仍可点。

### 5. 降级原因被误报成"离线模式"（用户报"为什么提示离线"）

- **根因**：前端用 `/本地|不可用|关闭/` 判断降级，而云端输出被一致性检查否掉时的说明里含「**本地**模板」四字 → 误报成"离线模式"，还补了一句"离线模式不会调用大模型"（与事实相反）。
- **真实链条**：云端调用**成功** → 输出与文献卡片对不上（2/6 句有依据，低于 35% 阈值）→ 退回模板。
- **修**：后端标记 `fallback_reason`（`offline` / `model_failed` / `ungrounded`），`/api/state` 透出，前端按原因分三种文案。

## 四、可复现性（重要，别改回去）

**问题**：草稿用 `temperature=0.3` 采样，两次生成相似度仅 77.3%、字数 1554 vs 1716 → 被审对象每次都变 → 自检结论（句数、论断数、支持率）每次都变。

**排查过程**（都是实测，不是推断）：

1. 同一份稿子连测两次 → 判断**稳定**（claims 8 / 有支撑 4 / 无支撑 4 / 支持率 0.5）。
2. 重新生成两次稿子 → **每次都变**。
3. 温度改 0 → **仍变**（1453 vs 1776）。
4. 温度 0 + **固定 seed**：短生成（27 字符）三次全同；**长生成仍变**（380 vs 623）。
5. 把多槽批处理 `-np` 降到 1 → **仍变**。结论：**llama.cpp 在 CPU 上无法保证长序列逐位可复现**。

**最终方案**：不拼运气，用确定性手段 —— **让本地生成也走缓存**（原先只有云端走）。同一输入第二次直接复用结果。

**实测**：同一输入连调两次 `_llm_draft`，sha 相同（`634d34858b6a`）；`generate()` 端到端跑两次均 1453 字符。

**相关开关**：`WM_DRAFT_TEMPERATURE`（默认 0）、`WM_DRAFT_SEED`（默认 20260918）。温度 >0 时自动放开 seed。

**边界**：缓存让**同一输入**可复现；换一批文献仍会生成不同的草稿 —— 这是生成式模型的本性，不要承诺"任何输入都一模一样"。

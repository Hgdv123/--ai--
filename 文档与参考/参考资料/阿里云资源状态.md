### 2.2 微调路径调整（因无 GPU 的应对）

原本计划 LoRA 微调 Qwen2.5-7B 需要 GPU。专区无 GPU 后，改为以下三条替代路径（择一或组合）：

| 路径 | 做法 | 可行性 |
|---|---|---|
| **A（推荐）** | 用**百炼平台自带的模型精调能力**（百炼支持在平台上做 SFT/LoRA，无需自己开 GPU 实例） | 需确认学生专区"大模型服务"类目内是否含精调额度 |
| **B** | 用 **Qwen-Plus + 严格 JSON Schema + 校验重试** 替代微调，把"结构化抽取"做到稳定 | 无需 GPU，成本极低（¥11.66/3个月包） |
| **C** | 自费短期租 GPU（不占用 300 元券），仅跑 1–2 轮 LoRA | 自费，约 40–80 元，可控但需额外决策 |

**默认执行 B（保底可交付），A 作为加分项（若专区确认支持），C 为备选。**

### 架构层面的应对（重要）

由于用券范围存在不确定性，代码架构必须做成**双通道**，不绑定单一云服务：

- **模型服务抽象层**：`百炼 API` 与 `本地推理 / 规则兜底` 双实现，切换只改配置；
- **检索层**：本地向量检索为主（纯 Python 余弦 + JSON 快照，**未使用 FAISS**），
  云端嵌入（百炼 text-embedding-v3）为可选增强；
- **对象存储**：本地文件系统为主，OSS 为可选。

这样即使券不能用、或某产品不在清单内，**作品依然能完整跑通并演示**。

### 2.3 演示方式决定：本地运行 + 录屏（2026-09-15 决定）

**决策**：**不购买 ECS，演示采用本地运行 + 录屏方式。**

| 影响面 | 变化 |
|---|---|
| 花费 | **省下 ¥68/年**（原计划买轻量应用服务器） |
| 部署架构 | **不需要服务器部署**：全部功能在本机跑，一条命令启动 |
| 演示视频 | 本机运行 + 录屏；决赛若需现场演示，再用本机 + 备份录屏 |
| 评委体验 | 少"可公网访问"这一加分项（赛题中"在线可访问"并非硬性要求） |
| 后续可逆 | 作品稳定后若想要公网访问，仍可随时买 ECS 补上，**代码无需改动** |

**由此产生的一条硬要求（必须落地，否则录屏会失败）**：

> **本项目必须能在"干净的本机环境"一键跑起来。**

具体要求（我会写进代码与 README）：

1. **单命令启动**：`python -X utf8 -m 源程序 demo` 或等价脚本，自动装依赖、自动建索引、自动开本地页面；
2. **不依赖任何云服务即可完整演示**：百炼 API 作为增强通道，网络异常时自动切本地规则兜底，**演示不中断**；
3. **零登录依赖**：演示流程中不得出现任何需要登录控制台的步骤；
4. **录屏友好**：
   - 首次运行要做的事（建索引、解析 PDF）提前跑完并缓存，录屏时只展示即时效果；
   - 界面在 1080p 下清晰可读，关键数字有视觉强调；
   - 提供 `demo/run_demo.md`：录屏前 10 分钟的检查清单（缓存就绪、网络、字体、分辨率）。

**验收标准**：在**未装过本项目依赖的干净目录**中，按 README 执行一条命令，**10 分钟内**完成"导入文献 → 出综述草稿 → 引用自检 → 导出 Word"，且**全程无需联网到阿里云**（有网时自动增强）。

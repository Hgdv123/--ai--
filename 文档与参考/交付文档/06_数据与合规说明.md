## 一、这份文档要回答什么

赛题明确要求提交"数据与合规说明"。我们把三件事讲清楚：

1. **用户的论文会被送到哪里？**（数据处理流程，含云端传输的完整披露）
2. **用了哪些数据？来源是否合法？**
3. **我们不做哪些事？**（学术诚信与合规边界）

## 二、用户论文的数据处理流程（重要披露）

### 2.1 云端处理路径（界面选择页上的默认项；**本提交包已预设为"仅本地"**，见本节末）

| 环节 | 具体行为 |
|---|---|
| **上传** | 用户选择本地 PDF → 写入本机 `data/pdf/` 目录。**PDF 原文件不上传至任何服务器。** |
| **本地解析** | 用 PyMuPDF 在本机抽取文本、章节、参考文献区，生成 `data/docs.json`。**此步不联网。** |
| **发送至云端** | 生成文献卡片时，把每篇论文的**标题、摘要片段（≤2600 字）、方法片段（≤1800 字）、结论片段（≤1500 字）**通过 HTTPS 接口发送至**阿里云百炼（DashScope）**，用于抽取"研究问题/方法/数据/指标/局限"。引用自检时，还会发送**正文论断（≤320 字）与检索到的原文片段（≤1400 字）**用于事实核对。 |
| **其他云端调用** | 生成综述正文、Agent 审稿、向量化（text-embedding-v3）同样调用阿里云百炼。 |
| **结果落盘** | 全部分析结果（卡片、矩阵、草稿、自检报告）**仅保存在用户本机**，不上传、不共享。 |

**必须明确告知用户的两点**：

1. **论文的部分文本内容会离开本机**，经加密传输至阿里云百炼进行处理；
2. 上传的 **PDF 原文件不会外传**，仅发送用于理解的文本片段。

**界面的告知方式（如实描述，含一处默认路径）**：首次打开时展示选择页，用户可主动选择
"云端处理"或"仅本地处理"，选择结果记录在 `data/privacy.json`（含确认时间戳）。
该页面**同时提供一个"直接进入应用（按默认的云端处理）"的链接**（`/?skip=1`），
点它即按云端处理记录确认——这一点在此写明，不宣称"不选就无法使用"。

**本提交包的默认状态**：`data/privacy.json` 为 `{"mode": "local", "acknowledged": true}`，
即**默认走仅本地处理**，评委无需任何 Key 即可完整跑通；填了 Key 也不会自动切到云端，
需要在界面上手动切换为「云端处理」。

### 2.2 仅本地处理路径（不联网）——**本提交包预设的就是这一条**

用户可选择**"仅本地处理"**，此时：

- **论文内容完全不离开本机**，不调用任何云端服务；
- 抽取与生成改用**随包本地模型**（Qwen2.5-3B + bge-small-zh 嵌入，llama.cpp 在本机跑），
  语义检索用本地 512 维向量；只有当本地模型也不可用时，才退到字符 n-gram 向量 + 规则模板；
- **能力边界（如实说明）**：正文**照常生成**、Agent 审稿也可用，全流程不联网；
  代价是质量低于云端，需逐句核对。
  只有连本地模型都不可用时，正文才退化为逐字取自卡片的模板（界面会明确告知）。

**适用场景**：文献涉及涉密课题、导师未发表成果、或用户出于任何原因不愿外传内容。
该选项的设置会持久保存，并在服务启动时自动生效。

### 2.3 数据流向图

```
用户 PDF（仅存本机）
      │
      ▼ 本机解析（PyMuPDF，不联网）
  文本片段
      │
      ├──[用户选择"仅本地处理"]──► 本机规则抽取 ──► 结果（仅存本机）
      │
      └──[用户选择"云端处理"]──► HTTPS ──► 阿里云百炼（通义千问 / text-embedding-v3）
                                              │
                                              ▼ 返回分析结果
                                        结果（仅存本机）
```

## 三、我们收集与不收集的数据

| 类别 | 处理方式 |
|---|---|
| 用户上传的论文 PDF | 仅存本机 `data/pdf/`，**不上传原文件** |
| 论文文本片段 | 云端处理模式下发送至阿里云百炼（已明确告知用户） |
| **个人信息** | **完全不采集**：无注册、无登录、无账号体系 |
| **使用行为数据** | **完全不采集**：无埋点、无统计上报、无第三方 SDK |
| **设备信息** | **不采集** |
| 网络请求 | 仅两类：向阿里云百炼发送分析请求；用户主动执行 `fetch` 时向 OpenAlex 检索论文元数据，失败会自动重试并退到 Crossref 备用接口 |

## 四、数据来源与授权

| 数据 | 来源 | 授权与合规 |
|---|---|---|
| 文献元数据（标题/作者/年份/摘要/引用数） | **OpenAlex**（api.openalex.org） | 开放学术数据，采用 CC0 公有领域声明，无需密钥即可访问 |
| 论文全文 PDF | **仅下载 OpenAlex 标记为"开放获取"（open access）的论文**（如 arXiv） | **不绕过任何付费墙**，不破解、不爬取需登录的内容 |
| 用户自带 PDF | 用户自行提供 | 由用户保证其来源合法；本工具仅在本机处理 |
| 示例数据（6 篇） | arXiv 开放获取论文 | 用于演示，均标注来源链接 |

**关于知网等商业数据库**：本工具**不抓取、不下载**知网等付费数据库的内容。
若用户希望使用从知网导出的**题录文本**，我们会解析该题录的**元数据字段**
（作者、题名、来源、年份），**不涉及全文抓取**。

| 事项 | 做法 |

## 七、学术诚信与使用边界

**文脉定位为写作与校对的助手，不是写作的替代者。**

| 我们不做 | 说明 |
|---|---|
| **不做代写** | 系统提供结构、引用与校对支持；学术判断与最终定稿由作者完成 |
| **不做降重** | 不提供任何规避查重或改写检测结果的功能 |
| **不生成完整论文** | 仅聚焦单一研究方向的 30–50 篇文献，完成综述场景的闭环 |
| **不替作者背书** | 所有引用判定均给出依据，并在报告中提示"建议人工复核" |

**给使用者的明确提醒**（已写入导出文档）：

1. 系统生成的引用判定可能出错，**必须由作者复核**；
2. 引用真实性核对依赖"已导入的论文原文"，若只导入题录则无法核对；
3. 使用本工具产出的学术成果，**学术责任由作者承担**。

## 八、安全措施

| 措施 | 实现 |
|---|---|
| 密钥管理 | API Key 存放于本机 `.env`，已在 `.gitignore` 中排除，**绝不进入代码仓库与提交包**；提交包仅含 `.env.example` 空模板 |
| 传输安全 | 所有云端调用走 HTTPS（`dashscope.aliyuncs.com`） |
| 路径安全 | 删除论文时校验路径必须位于 `data/pdf/` 之下，防止越权删除 |
| 无远程服务 | 本工具**不部署公网服务**，只在用户本机 `127.0.0.1` 提供页面，外部无法访问 |
| 成本与滥用防护 | 单日 API 成本上限、结果缓存（模型分级路由已留配置位，**当前未启用**） |
| 可退出 | 用户可随时清空文献库、删除单篇论文、切换为纯本地处理 |

## 十、已知限制与如实说明

| 项 | 说明 |
|---|---|
| **本工具未做数据脱敏** | 若论文中包含个人隐私信息（如涉及人类受试者的研究），这些内容会随文本片段发送至云端。**建议：此类文献请使用"仅本地处理"模式** |
| **未做端到端加密** | 依赖 HTTPS 传输层加密，未额外做内容级加密 |
| **云端服务方条款** | 阿里云百炼对输入数据的处理以其服务条款为准；本项目不使用用户数据训练模型，亦不将数据用于本项目之外的用途 |
| **模型可能出错** | 引用判定为辅助参考，最终由作者负责 |

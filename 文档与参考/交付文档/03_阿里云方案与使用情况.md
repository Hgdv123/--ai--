# 阿里云方案与使用情况

> 2026 年第二届重庆市 AI 大模型创新应用大赛 · 企业出题赛道（阿里「创意 AI 校园」）
>
> 赛题要求「**需要使用阿里云产品或平台**」。本文说明用了哪些、用在哪儿（含代码位置）、
> 实测成本与降级行为，以及如实说明**没有**用到的部分。

## 一、结论速览

| 阿里云产品 | 用途 | 是否必需 | 代码位置 |
|---|---|---|---|
| **百炼（DashScope）大模型服务** | 正文草稿、文献卡片增强 | 核心，云端模式必需 | `代码/源程序/llm.py` |
| └ `qwen-plus` | **唯一实际使用的模型**（正文草稿、卡片增强、Agent 判定） | 是 | `config.py:105` |
| ├ `qwen-turbo` | 预留档位，**当前不生效**（详见 §2.1） | 否 | `config.py:106` |
| └ `qwen-max` | 预留档位，**当前不生效**（想用请改 `MODEL_DEFAULT`） | 否 | `config.py:107` |
| **百炼文本嵌入 `text-embedding-v3`** | 语义向量（RAG 的语义通路） | 否（可降级本地） | `代码/源程序/embeddings.py:27,186,208` |
| **阿里云 PyPI 镜像** | 依赖自动安装的备用源 | 否（多源之一） | `代码/源程序/bootstrap.py:52` |

**接入方式**：百炼的 **OpenAI 兼容模式**（`https://dashscope.aliyuncs.com/compatible-mode/v1`），
只用 Python 标准库 `urllib` 发起请求，**不依赖任何云厂商 SDK**。
这样做的理由：交付包体积可控、离线安装更简单、换模型或换厂商时只改一处配置。

## 二、大模型服务的使用方式

### 2.1 模型配置：当前只启用一个档位

三个档位都在 `.env` 里可配，但**当前实现只读取并使用 `MODEL_DEFAULT`**，另两档是预留项：

| 档位 | 默认值 | 配置项 | **当前是否生效** |
|---|---|---|---|
| 默认 | `qwen-plus` | `MODEL_DEFAULT` | ✅ **生效**——所有云端模型调用都走这一档 |
| 省钱 | `qwen-turbo` | `MODEL_CHEAP` | ⬜ **预留，当前不生效** |
| 难题 | `qwen-max` | `MODEL_STRONG` | ⬜ **预留，当前不生效** |

**为什么另两档没用上**：判断"哪一步算难题、哪一步算简单"需要一个可靠的分级依据。
在本项目的调用规模下（一次草稿 + 每篇一次卡片增强 + 若干次核对判定），
分级带来的成本节省有限，而分错的代价是正文质量下降却不易察觉。
因此在当前版本里选择**只用一档、把它设对**，而不是引入一个尚不可靠的分级器——
这与本文 §2.2 的取舍思路一致：宁可少一个功能，不要多一个说不清的行为。

> **实测确认**：`代码/源程序/` 全包搜索 `model_strong` / `model_cheap`，
> 除 `config.py` 中的定义外**无任何引用点**；所有云端调用的模型名均取自
> `settings.model_default`（`llm.py` 的 `chat()` / `chat_json()`、`agent.py` 的工具调用）。
> 因此**改 `MODEL_CHEAP` / `MODEL_STRONG` 不会产生任何效果**，想换模型请改 `MODEL_DEFAULT`。

### 2.2 三个调用点及其设计考虑

**① 正文草稿**（`llm.py`，一次调用）

把归并好的主题与文献卡片交给 qwen-plus，一次生成整篇正文。**只调用一次**是刻意的：
分多次调用会让成本与耗时都翻倍，而综述正文的结构并不需要多轮交互。

超时策略：`max(60, 60 + max_tokens/1000×30)` 秒。原为固定 60 秒，实测生成接近 60 秒时
会被掐断，而用户看到的是"失败"而不是"生成到一半"，因此改为随输出规模放宽。

**② 卡片增强**（`cards.py`，每篇一次）

文献卡片采用「本地规则打底 + 模型增强」两段式。规则段不依赖模型，模型段负责把候选内容
规范化为结构化字段。**模型不可用时跳过增强，卡片照常可用**——这是离线可运行性的基础。

**③ 论断核查**（`selfcheck.py`）

把检索到的原文片段交给模型，逐条判断"这些片段能否支撑该论断"。
这一环**只在启用模型时才有独立判断能力**；未启用时退化为相似度阈值兜底（详见 §4 与评测报告）。

### 2.3 成本护栏

| 机制 | 实现 |
|---|---|
| 单日上限 | `DAILY_COST_LIMIT_YUAN=20`（`config.py:110`） |
| 超限行为 | **拒绝云端调用并自动转本地通道**，不是报错中断 |
| 台账 | `代码/源程序/.cache/cost_ledger.json` 按日累计调用数、token 数、花费 |
| 缓存 | `ENABLE_CACHE=true`，相同请求命中缓存不重复计费 |

**实测成本**（本机实测，非估算）：

| 场景 | 花费 |
|---|---|
| 单次草稿调用（约 15 s / 879 字符） | **¥0.0019** |
| 6 篇论文完整一轮（解析→卡片→矩阵→草稿→自检→导出） | **约 ¥0.011** |
| 按 ¥20 日上限估算可支撑轮数 | 约 1800 轮 |

## 三、文本嵌入服务的使用方式

### 3.1 为什么需要它

RAG 的检索由两路召回 + RRF 融合组成：

| 通路 | 实现 | 作用 |
|---|---|---|
| 词法 | BM25（自实现，含中文分词） | 精确术语、缩写、数字 |
| **语义** | **百炼 `text-embedding-v3`（1024 维）** | 同义改写、**跨语言**（中文论断 ↔ 英文论文） |
| 融合 | RRF（`k=60`） | 合并两路排名 |

语义通路在本作品中格外重要：**论文多为英文，而生成的论断是中文**，单靠词法几乎匹配不上。
云端模式下由模型生成英文检索词 + 1024 维语义向量共同解决这个问题。

### 3.2 三路降级（保证离线可用）

| 优先级 | 后端 | 维度 | 触发条件 |
|---|---|---|---|
| ① | 百炼 `text-embedding-v3` | 1024 | 配好 Key 且未超限 |
| ② | 本地 `bge-small-zh-v1.5-q8_0` | 512 | 云端不可用，本地模型可用 |
| ③ | 字符 n-gram 哈希向量 | 2048 | 两者都不可用（零依赖保底） |

**关键实现细节**：缓存键包含**后端标识**（`embeddings.py:32-33`）。
不同后端的向量维度与语义空间完全不同，**混用会导致检索结果静默错乱**，
因此"云端 1024 维"与"本地 512 维"的向量绝不共用缓存。

> 这一点是在排查检索异常后补充的：缓存键若只用文本内容，切换模式后会读到另一后端的向量，
> 表现为"检索结果莫名其妙"，且极难排查。

### 3.3 批量与进度

`_remote_embed` 按 **10 条一批**提交（`embeddings.BATCH = 10`，百炼单次上限），
并打印批次进度与失败原因。原实现无进度输出，界面在几百次请求期间无任何反馈，
用户以为程序卡死。

## 四、降级链与"必须使用阿里云"的落实

```
① 云端通道（阿里云百炼）        ← 赛题要求落实在这里：默认通道
   qwen-plus 生成 + text-embedding-v3 嵌入
        │ 无 Key / 超日限 / 用户选「仅本地」
        ▼
② 本地通道（随包 llama.cpp）
   Qwen2.5-3B-Instruct + bge-small-zh-v1.5
        │ 本地模型也不可用
        ▼
③ 规则通道（确定性）
   逐字取自文献卡片的模板 + 四类不依赖模型的检查
```

**本提交包默认走「仅本地处理」**：`.env` 里配好 Key 也**不会**自动切到云端——必须先在界面顶部把处理方式切到「云端处理」。这样设计是为了保证：在用户没有明确选择之前，论文内容不会离开本机。
界面状态条常驻显示当前处理方式（「云端处理」/「仅本地处理」），用户随时知道数据去了哪里。

**降级不是全有全无**：即使降到第 ③ 级，「引用真实性 / 编号顺序 / GB/T 7714 格式合规 /
重复著录」四类检查**仍然全部有效**，因为它们的实现不依赖模型。

## 五、如实说明：没有用到的部分

以下内容**没有使用**，列出来是为了让评审的判断有依据：

| 项目 | 情况 |
|---|---|
| **天池数据集** | **未使用**。赛题将天池数据集列在「赛题资源」而非硬性要求中。本项目自备验证集（6 篇真实论文 + 4 类专家注入错误），原因见 `文档与参考/交付文档/02_验证集评测结果.md`。评测脚本已预留 `代码/评测/external/` 接口，可接入天池 CSL 等外部语料。 |
| **阿里云 GPU 实例 / PAI 训练** | **未使用**。本项目在做完成本与收益评估后决定不做模型微调：微调需要 GPU 资源与标注数据，而实测表明主要问题不在模型能力，而在**引用编号的对应关系**（详见《模型与算法说明》§6.2）。用提示词工程 + 确定性校验解决，成本低一个量级且可解释。 |
| **阿里云 OSS / RDS / 函数计算** | **未使用**。本作品为单机桌面应用，数据存本地文件系统，用户论文不出本机（离线模式下完全不联网）。引入云存储会与"论文不出本机"的隐私承诺冲突。 |
| **百炼模型微调服务** | **未使用**，理由同上。 |

**用券情况**：见 `文档与参考/参考资料/阿里云资源状态.md`（含学生优惠券的适用规则核查记录与待核验清单）。
该文档中的待核验项需账号持有人登录确认，我无法代查，故保持原样未作推测性填写。

## 六、可复现的验证方式

```bash
# 注意：包目录名是「源程序」，命令需在 代码/ 目录下执行

# 1. 确认云端通道确实在工作（会打印模型名、耗时、花费与台账变化）
python -X utf8 -c "
import os; os.environ['WM_OFFLINE']='0'
from 源程序.llm import LLMClient
c = LLMClient()
print('available =', c.available, '| cloud =', c.cloud)
print(c.chat([{'role':'user','content':'用一句话说明什么是元学习。'}], max_tokens=64))
"

# 2. 查看成本台账
type 源程序\.cache\cost_ledger.json

# 3. 确认嵌入后端与向量维度（云端 1024 维 / 本地 512 维 / 保底 2048 维）
python -X utf8 -c "
import os; os.environ['WM_OFFLINE']='0'
from 源程序 import embeddings
print('优先后端 =', embeddings.EMBED_MODEL)
emb = embeddings.Embedder()
vs = emb.encode(['元学习与少样本分类'])
print('实际维度 =', len(vs[0]))
"
```

> **提醒**：随包的 `代码/源程序/.cache/` 内含历史云端调用结果。
> 用无效 Key 时，这些缓存仍可能让流程"看起来跑通了云端"。
> 要验证云端通道真的可用，请先清空该缓存，再用**有效 Key**运行上述第 1 条。

## 七、小结

- **阿里云用在核心链路上**：百炼的大模型服务与文本嵌入服务是默认通道，不是摆设；
  正文草稿、卡片增强、语义检索三处都实打实依赖它。
- **成本可控且可验证**：6 篇论文一轮约 ¥0.011，有日上限护栏与按日台账，超限自动降级。
- **降级不牺牲正确性**：四类确定性的引用与格式检查完全不依赖模型，离线也全部有效。
- **未使用的能力如实列出**：天池数据集、GPU 训练、模型微调、云存储均未使用，并说明了原因。
